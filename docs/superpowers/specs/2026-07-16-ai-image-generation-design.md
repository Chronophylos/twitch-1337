# AI Image Generation (OpenRouter + imgdrip) — Design

Status: approved
Date: 2026-07-16
Branch: `feature/ai-image-gen`

## Goal

Let `!ai` and `@grok` generate or edit images via an agent tool when the user asks for create/edit. Each path has its own enable toggle and OpenRouter image model. Generated bytes are rehosted on imgdrip so Twitch chat gets a stable public URL.

## Non-goals (v1)

- Native xAI Imagine client / second API key
- Catbox (or other host) fallback
- Streaming partial images
- Auto second PRIVMSG from the hoster layer
- Separate image rate limits / quotas
- Hard classifier that blocks tool calls without a create/edit ask
- Reusing AI · Media (vision analysis stays separate)

## Product decisions

| Decision | Choice |
|---|---|
| Who | Both `!ai` and `@grok`, independent enable + model |
| Trigger | Tool always registered when enabled; prompt steers create/edit-only |
| Backend | OpenRouter `POST /api/v1/images` |
| Delivery | `b64_json` → imgdrip upload → URL in model final reply |
| Secrets | Reuse existing AI API key; no new `config.toml` field |

## Settings

```rust
pub struct AiImageGen {
    pub enabled: bool,
    pub model: String,
    pub timeout_secs: u64,
    pub host: ImageHostKind, // imgdrip
}

pub struct AiGrokImageGen {
    pub enabled: bool,
    pub model: String, // no fallback to ai.image_gen.model
}

// On AiGrok:
pub image_gen: AiGrokImageGen;
```

| Key | Role |
|---|---|
| `ai.image_gen.enabled` / `.model` / `.timeout_secs` / `.host` | `!ai` path |
| `ai.grok.image_gen.enabled` / `.model` | `@grok` path |

Defaults: both disabled; empty models; `timeout_secs` ~90; host `imgdrip`. Hot-reload via `SettingsHandle`.

UI:

- New **AI · Image gen** card (card toggle + model + timeout); OpenRouter-gated like grok `service_tier`
- **AI · Grok**: image-gen subsection (toggle + model)
- Model datalist from OpenRouter image-models (`/api/v1/images/models` or filtered models endpoint)

## Architecture

```
!ai / @grok
  → resolve ImageGenRuntime for path
  → if enabled + model non-empty: register generate_image + prompt rule
  → run_agent
  → generate_image(prompt, input_image_urls?, aspect_ratio?)
       → OpenRouterImageClient POST /images (n=1)
       → ImgdripHost multipart upload
       → tool result { url }
  → model final text includes URL → existing say/reply
```

Components:

| Component | Crate | Job |
|---|---|---|
| `OpenRouterImageClient` | `llm` | Auth + `POST {base}/images`; parse `b64_json` / `media_type` |
| `ImageHost` + `ImgdripHost` | `core` | `POST https://imgdrip.com/api/upload` field `file` |
| `generate_image` tool | `core` | Agent-facing create/edit |
| Runtime resolve | `core` settings + `AiCommand` | Per-path enable/model |

Tool args: `prompt` (required), `input_image_urls` (optional, max 4), `aspect_ratio` (optional). One image per call.

Prompt rule (when tool registered): only call when the user asked to create or edit an image; include the returned URL in the final chat reply.

## Errors and limits

- Tool failures → short model-visible error; turn continues
- Caps: 4 input URLs; ~10 MiB decoded bytes; `n=1`
- Existing AI per-user cooldown only
- Log model/latency/hoster/success; never log base64 bodies

## Testing

- Unit: resolve matrix, response parse, imgdrip wiremock, arg validation
- Integration: mocked gen+host → URL in tool result/say; disabled → tool absent
- Web: POST forms for both cards
- No live OpenRouter/imgdrip in CI
